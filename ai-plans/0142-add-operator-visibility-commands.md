# Add operator visibility commands

> Issue: [#142](https://github.com/chA0s-Chris/ShadowDrop/issues/142)

## Rationale

Give operators safe, scriptable API and CLI views of server health, compatibility, and share lifecycle state without requiring direct persistence access. Keep public responses minimal, require administrative authorization for operational detail, and make every response an explicit projection that cannot disclose bearer tokens, token hashes, encryption material, storage locations, configuration secrets, or raw failures. The scoped upload-credential model from #139 is now available and must be reused without treating the bootstrap admin token as an upload-scoped credential. Issue #142 is an umbrella coordinated through child issues [#170](https://github.com/chA0s-Chris/ShadowDrop/issues/170) for server status, [#171](https://github.com/chA0s-Chris/ShadowDrop/issues/171) for share listing, and [#172](https://github.com/chA0s-Chris/ShadowDrop/issues/172) for share inspection; this file is not an implementation unit and must not be passed to `implement-plan`. Each child must receive its
own issue-numbered plan, branch, pull request, tests, auditing, and documentation.

## Technical Details

**Delivery model.** Keep #142 as the coordination and design source for the three ordered child workstreams below. The child issue plans must copy the applicable constraints from this plan, resolve any workstream-specific questions before implementation, and remain independently testable and reviewable. Do not create multiple `0142-*` sub-plans and do not invoke `implement-plan` for this umbrella plan.

**Shared protocol and security contract.** Put shared protocol constants and source-generated JSON contracts in `ShadowDrop.Shared` where both the API and Native AOT CLI can use them. Introduce explicit response records rather than returning persistence records or anonymous objects. Keep `/health/live` and `/health/ready` as minimal orchestrator probes. Operational protocol version `1` has a CLI-supported inclusive range of `[1, 1]`; clients ignore unknown additive fields, while removing or changing fields, endpoint shapes, nullability, reason semantics, or filter/cursor semantics requires a protocol-version change.

`GET /api/status` is public, `GET /api/status/upload` requires a valid scoped upload credential, and `GET /api/admin/status`, `GET /api/admin/shares`, and `GET /api/admin/shares/{shareId}` extend the `AdminEndpoints` route group and require `RequireAdminBearerToken`. `GET /api/admin/shares/{shareId}` accepts `includeFilenames=false` by default; only the authenticated admin route may set it to `true`. The child plans own these response contracts:

| Contract         | Required camel-case JSON fields                                                                                                                                                                                                                         |
|------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Public status    | `protocolVersion` (integer), `live` (Boolean), `ready` (Boolean), `reason` (string), and `capabilities` containing the Boolean fields `publicDownloads`, `adminOperations`, `resumableDownloads`, and `scopedUploads`                                   |
| Upload status    | All public-status fields plus `effectiveLimits`, containing nullable `maxFileBytes`, `maxShareBytes`, and `expiresAtUtc` fields; `null` means the authenticated credential has no such constraint                                                       |
| Admin status     | All public-status fields plus `buildVersion`, `uptimeSeconds`, `components`, `providers`, `storage`, `shares`, `cleanup`, `resumableSessions`, and `configurationWarnings`                                                                              |
| Share page       | `items`, `nextCursor`, and `totalMatching`; each summary item contains `shareId`, `createdAtUtc`, `expiresAtUtc`, `revokedAtUtc`, `statuses`, `cleanupState`, `lastCleanupAttemptAtUtc`, `cleanupFailureCategories`, `fileCount`, and `ciphertextBytes` |
| Share inspection | The summary fields plus `files`; each file contains `fileId`, `ciphertextBytes`, `originalFilename`, and `displayName`, with both filename fields `null` unless the admin-authorized filename opt-in was requested                                      |

Public `reason` is always present and is one of `none`, `dependency-unavailable`, `dependency-timeout`, or `configuration-invalid`. Component `state` is one of `ready`, `not-ready`, or `not-applicable`, and its `reason` uses the public set plus `capability-disabled`. Arrays are empty rather than `null`; only explicitly nullable fields may be `null`; fields are not conditionally omitted; and timestamps use UTC ISO 8601 round-trip strings. Non-status errors use `{ "reason": string }`: invalid requests return `400` with `invalid-request`, missing or invalid credentials return `401` with `unauthorized`, unknown shares return `404` with `not-found`, and malformed or query-mismatched cursors return `400` with `invalid-cursor`. Status endpoints return `200` when ready and `503` when not ready while retaining the same response shape.

**Server-status child ([#170](https://github.com/chA0s-Chris/ShadowDrop/issues/170)).** Implement the public, upload-authorized, and administrative status API projections and the `server status` CLI command as one vertical workstream. Default CLI mode always calls `GET /api/status`; `--upload-authorized` calls `GET /api/status/upload` using normal upload-token resolution; and `--verbose` calls `GET /api/admin/status` through the existing `CliConfigurationResolver.ResolveAdmin` and `AdminConfiguration` path. Reject `--upload-authorized` with `--verbose`. Credentials present only in environment or configuration do not change the selected endpoint, and `--json` changes rendering only.

Extend `UploadCredentialAuthorizationContext` and `UploadCredentialService.AuthenticateAsync` with the authenticated credential's nullable expiry so the upload projection can expose `expiresAtUtc` without revealing its management ID or token lookup material. Reuse the existing nullable file/share byte limits. Protocol version `1` has no usage-count field because #139 defines no usage-count constraint.

Introduce `IOperationalDependencyProbe`, returning only an allow-listed component name, state, and reason. Register probes for configured metadata and blob-storage dependencies and aggregate them through an evolved structured `IReadinessCheck`. Ping a physical MongoDB dependency shared by metadata and GridFS once and project its result onto the affected logical components. LiteDB uses a bounded metadata operation and filesystem storage uses a non-destructive root-accessibility check. Give each physical probe a linked cancellation deadline defaulting to five seconds; deadline expiry maps to `dependency-timeout`, provider failure to `dependency-unavailable`, and caller cancellation propagates.

Aggregate status through a dedicated service registered by `DependencyInjection`. It uses `ShadowDropOptions`, a process-start timestamp based on `TimeProvider`, dependency-probe results, provider statistics, share-status counts, and cleanup-run state. Exact build version, provider names, totals, dependency detail, cleanup state, and warning codes are admin-only. Public output collapses failures to coarse reason categories.

Current storage totals must describe blobs known to remain retained, not all completed upload metadata. Add persisted retention/accounting state to uploaded-file metadata: new completed uploads are `retained`, a successful cleanup deletion or already-missing result transitions the file atomically to `deleted`, and pre-existing records without state are `unknown`. `IUploadedFileMetadataRepository` computes `completedFileCount` and `ciphertextBytes` only when no unknown records prevent an exact result; otherwise the admin fields are `null` and `configurationWarnings` contains a stable `storage-accounting-incomplete` code. Do not scan filesystem, GridFS, or S3 inventories to repair or calculate these totals.

Cleanup-run status is process-local and resets on startup to `lastRunAtUtc: null` and `lastOutcome: "not-run"`. An atomic singleton records completion time through `TimeProvider` and one of `success`, `partial-failure`, `failure`, or `skipped`. Caller cancellation leaves the previously completed outcome unchanged. Persistent or historical cleanup-run reporting is out of scope.

The status child maps connectivity/TLS, readiness, authorization, and compatibility outcomes centrally to the agreed CLI exit codes. Its admin endpoint emits an `admin-status-view` audit event containing only operation, outcome, HTTP status, and elapsed time. Stable outcomes are `success`, `unauthorized`, `invalid-request`, `cancelled`, and `failure`; the authorization filter or surrounding middleware records unauthorized attempts without recording the supplied credential.

**Share-list child ([#171](https://github.com/chA0s-Chris/ShadowDrop/issues/171)).** Add a query model and cursor page result to `IShareMetadataRepository`, implemented by `LiteDbShareMetadataRepository` and `MongoShareMetadataRepository`. The child plan must choose and document stable, matching HTTP query parameters and CLI options for the repeatable lifecycle filter, page size, and cursor before implementation starts.

Capture one `nowUtc` for each query. `active` means not revoked and expiring after `nowUtc`; `expired` means expiring at or before `nowUtc`; `revoked` means a revocation timestamp is present; `cleanup-pending` means cleanup is pending and the share is expired or revoked; and `cleanup-failed` and `cleanup-completed` are exact cleanup-state matches. Predicates are independent, repeated filters combine with OR, no filter returns all shares, and totals count each matching share once.

Use a default page size of `50` and maximum of `200`; reject invalid sizes with `400` and `invalid-request`. Order by descending `(CreatedAtUtc, ShareId)` with the tie-breaker compared as a canonical lower-case UUID `D` string using ordinal semantics. Continue strictly after the cursor position. Encode protocol version, sort position, and normalized filters in the opaque cursor; reject malformed or query-mismatched cursors with `invalid-cursor`. Return exact provider-side `totalMatching` and document that totals may change between requests.

Add provider-appropriate indexes for timestamp, cleanup, expiration, revocation, and stable tie-breaker predicates. Extend `IUploadedFileMetadataRepository` with a bounded batch projection so summaries can calculate ciphertext sizes without N+1 reads. Extend share cleanup metadata with `LastCleanupAttemptAtUtc` and the latest completed attempt's distinct sanitized categories: `upload-metadata-missing`, `metadata-unavailable`, `blob-delete-failed`, and `unknown`. Atomically replace state, timestamp, and categories after each completed attempt; successful attempts store an empty category set, retries replace prior outcomes, cancellation records nothing, and existing records deserialize with a null timestamp and empty categories. Never persist raw exceptions.

Map persistence records into allow-listed summary DTOs that omit share-token hashes, download-token data, blob keys, cryptographic metadata, plaintext hashes, filenames, and credential identifiers. Emit `admin-share-list` audit events using the shared safe audit contract.

**Share-inspection child ([#172](https://github.com/chA0s-Chris/ShadowDrop/issues/172)).** Reuse the share-summary projection and bounded file-metadata lookup to return one share's detailed lifecycle and storage view. Share and file IDs are lower-case UUID `D` strings. Filename fields remain `null` unless `includeFilenames=true` is requested through the admin endpoint and `--include-filenames` is selected in the CLI. The child returns the shared `not-found` contract and exit code `6` for an unknown share. It must not create a path from an internal share ID to a usable download capability. Emit `admin-share-inspect` audit events using the shared safe audit contract.

**Cross-workstream verification and documentation.** Cover endpoint authorization and projections in `ShadowDrop.Api.Tests`, CLI rendering and exit behavior in `ShadowDrop.Cli.Tests`, and provider/index parity in the existing LiteDB and MongoDB fixtures. Each child must include fixtures large enough for its bounds and failure cases without introducing expensive unbounded test scans. Audit tests assert every applicable outcome and verify prohibited values are absent from captured events. Update `README.md`, `docs/API.md`, `docs/CLI.md`, `docs/DEPLOYMENT.md`, and `docs/SECURITY_TRADEOFFS.md` incrementally so the final documentation contains the exact field matrix, routes, supported reasons, exit codes, credential modes, JSON examples, pagination contract, and filename sensitivity guidance.
