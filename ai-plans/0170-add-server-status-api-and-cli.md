# Add server status API and CLI

> Issue: [#170](https://github.com/chA0s-Chris/ShadowDrop/issues/170)

## Rationale

Give operators a fast, scriptable preflight for server reachability, liveness, readiness, protocol compatibility, dependency state, and safe operational totals. Expose each field at the least-privileged useful tier, keep failure categories stable, and ensure neither degraded dependencies nor retained-storage accounting can leak secrets or leave the CLI hanging.

## Acceptance Criteria

- [ ] Add operational protocol version `1` with a CLI-supported inclusive range of `[1, 1]` and shared source-generated contracts in `ShadowDrop.Shared`.
- [ ] Add explicit public `GET /api/status`, scoped-upload-authorized `GET /api/status/upload`, and admin-authorized `GET /api/admin/status` projections.
- [ ] Preserve `/health/live` and `/health/ready` as minimal orchestrator probes with their existing route purpose and response surface.
- [ ] Add `shadowdrop server status` with public default, mutually exclusive `--upload-authorized` and `--verbose` tiers, and a `--json` rendering mode that never changes authorization or endpoint selection.
- [ ] Do not let credentials found only in environment or configuration silently elevate the selected status tier.
- [ ] Distinguish unreachable, live-but-not-ready, ready, unauthorized, capability-disabled, and protocol-incompatible CLI outcomes.
- [ ] Use exit code `0` for healthy/compatible, `2` for unhealthy/not-ready, `3` for connectivity or TLS failure, `4` for authorization failure, `5` for protocol incompatibility, and `1` for usage, capability-disabled, or unexpected failures.
- [ ] Reuse the existing admin-token configuration path and extend successful scoped-upload authentication with nullable credential expiry; protocol version `1` has no usage-count field.
- [ ] Probe every configured physical metadata/blob dependency once per status request through bounded, cancellable operational probes with a five-second default timeout.
- [ ] Run operational probes and statistics reads under one five-second default status-collection deadline, returning null statistics with stable degraded reasons or warnings rather than `500` for expected provider failures or timeouts.
- [ ] Expose only allow-listed component names and stable reasons: `none`, `dependency-unavailable`, `dependency-timeout`, and `capability-disabled` where applicable.
- [ ] Keep the public status endpoint operational when every API capability is disabled by registering status probes independently and using capability-gated optional statistics collaborators.
- [ ] Return `401` for invalid, expired, or revoked scoped-upload credentials, but return a public-safe `503` without an upload projection when credential lookup or usage recording cannot complete because the metadata provider is unavailable or times out.
- [ ] Report current retained-blob totals from persisted accounting state rather than all completed upload metadata or filesystem, GridFS, or S3 inventory scans.
- [ ] Persist `retained` for newly completed uploads, transition successful or already-missing cleanup results to `deleted`, and treat legacy records without state as `unknown`.
- [ ] Return null storage totals with the stable `storage-accounting-incomplete` warning whenever unknown records prevent an exact result.
- [ ] Track cleanup-run status process-locally with `not-run`, `success`, `partial-failure`, `failure`, and `skipped`; reset it at startup and preserve the previous completed outcome on caller cancellation.
- [ ] Emit concise deterministic human output and exactly one documented JSON result on stdout whenever `server status` and `--json` are recognized, including parsing, option-validation, configuration, and TLS-setup failures, while keeping banners and diagnostics off stdout.
- [ ] Emit safe `admin-status-view` audit events containing only operation, outcome, HTTP status, and elapsed time.
- [ ] Never expose credentials, token material or hashes, credential identifiers, connection details, database hosts, storage paths or keys, raw configuration values, or internal exception text.
- [ ] Provide equivalent response, probe, retained-accounting, timeout, and degraded-dependency behavior for LiteDB/filesystem and MongoDB/GridFS deployments, including S3 when configured.
- [ ] Add automated authorization, contract, redaction, stdout/stderr, exit-code, timeout, cancellation, degraded-dependency, retained-accounting, audit, Native AOT serialization, and provider-parity tests.
- [ ] Update `README.md`, `docs/API.md`, `docs/CLI.md`, `docs/DEPLOYMENT.md`, and `docs/SECURITY_TRADEOFFS.md` with routes, modes, fields, reason values, exit codes, credential requirements, examples, and sensitivity guidance.

## Technical Details

Introduce versioned status records and constants under `ShadowDrop.Shared` so the API and Native AOT CLI share one JSON contract. Public status contains `protocolVersion`, `live`, `ready`, `reason`, and `capabilities` with `publicDownloads`, `adminOperations`, `resumableDownloads`, and `scopedUploads`. Upload-authorized status adds `effectiveLimits` with nullable `maxFileBytes`, `maxShareBytes`, and `expiresAtUtc`. Admin status adds `buildVersion`, `uptimeSeconds`, `components`, `providers`, `storage`, `shares`, `cleanup`, `resumableSessions`, and `configurationWarnings`. Keep all fields present, emit arrays as empty rather than null, use UTC ISO 8601 round-trip timestamps, and reserve null for explicitly unavailable values.

Use stable nested shapes: components contain `name`, `state`, and `reason`; providers contain stable metadata and storage provider names; storage contains nullable 64-bit `completedFileCount` and `ciphertextBytes`; shares contains 64-bit `active`, `expired`, `revoked`, `cleanupPending`, `cleanupFailed`, and `cleanupCompleted`; cleanup contains nullable `lastRunAtUtc` and required `lastOutcome`; resumable sessions contains nullable `activeCount`; and configuration warnings is an array of stable codes. Count share states from one captured `nowUtc`: active, expired, and revoked are lifecycle predicates, while cleanup pending/failed/completed are cleanup predicates, so counts may overlap and match the later share-list semantics. Stateless client-managed download resume reports no active server-session count rather than inventing zero.

Map status endpoints through a dedicated `StatusEndpoints` extension from `Middleware`, while adding the admin projection to the existing `AdminEndpoints` route group. The public endpoint is always anonymous and reports only coarse state and capability availability. The upload endpoint uses a scoped-upload-only filter built on `UploadCredentialService`; it must reject the bootstrap admin token and place the authenticated authorization context on `HttpContext`. Invalid, expired, or revoked credentials return `401`. Catch expected credential-repository timeout or unavailability separately and return a bodyless, public-safe `503` so no upload limits are disclosed and the exception does not escape as `500`. The admin endpoint continues through `RequireAdminBearerToken`. Map the upload route only when scoped uploads are enabled and the admin route only when admin operations are enabled, with public capabilities describing disabled surfaces.

Return the same selected projection with `200` when ready and `503` when not ready, except for the explicitly bodyless upload-authentication provider failure described above. `live` is true whenever the API produced a status response. Choose public reason deterministically with `dependency-timeout`, `dependency-unavailable`, then `none` precedence; startup configuration validation remains fail-fast, so protocol version `1` has no `configuration-invalid` reason. Component state is `ready`, `not-ready`, or `not-applicable`; component reasons use the public set plus `capability-disabled`. Exact build and provider information stays admin-only. Compatibility is a client conclusion based solely on the operational protocol range, not product-version equality.

Evolve `UploadCredentialAuthorizationContext` and `UploadCredentialService.AuthenticateAsync` to include the matched credential's nullable `ExpiresAtUtc` alongside its existing byte limits. Do not expose `CredentialId`, selector digests, names, usage timestamps, or any token-derived value in status projections. Reuse `CliConfigurationResolver.Resolve` for the explicitly selected upload tier and `CliConfigurationResolver.ResolveAdmin`/`AdminConfiguration` for the explicitly selected admin tier.

Replace the Boolean-only dependency result with a structured readiness result aggregated from `IOperationalDependencyProbe` implementations. Each physical probe returns only its allow-listed logical component mappings, state, and reason; it never returns exception text or configuration values. Ping a MongoDB dependency shared by metadata and GridFS once, reuse the S3 bucket check, add a bounded LiteDB metadata operation, and add a non-destructive filesystem-root accessibility check. Run independent physical probes and operational-statistics reads concurrently under one five-second default status-collection deadline so total latency is bounded rather than additive. Skip statistics that depend on an already unavailable component where possible. Caller cancellation propagates, while the collection deadline maps to `dependency-timeout` and other expected provider failures map to `dependency-unavailable`; affected statistics remain null and receive the applicable stable warning instead of
producing `500`. Adapt `/health/ready` to the structured result without expanding its response body.

Add an `OperationalStatusService` singleton through `DependencyInjection`. Register it and the physical operational probes independently of API exposure. Capture process start once from `TimeProvider`, obtain an immutable dependency snapshot, and project only the selected authorization tier. Read upload storage/reservation statistics and share counts through explicitly optional, capability-gated collaborators so constructing or executing the public projection never requires a repository that is not registered for the configured exposure. Resolve the API build version from assembly informational version with build metadata stripped, matching `CliVersion` behavior. Disabled or unsupported statistics remain null and their capability/component state explains why. Cover a configuration with every operational API capability disabled to prove that public status still resolves and responds.

Make retained storage explicit in `UploadedFileRecord`, `LiteDbUploadedFileMetadataRepository`, `MongoUploadedFileMetadataRepository`, and their persistence documents through a small `BlobRetentionState` model. Completed uploads write `retained`; missing fields deserialize as `unknown`. Extend `IUploadedFileMetadataRepository` with an atomic transition that marks a completed file `deleted` after `IBlobStorage.DeleteIfExistsAsync` succeeds or confirms absence. If that metadata transition fails, `ShareCleanupService` treats the share cleanup as failed so retry can reconcile the conservative overcount; no cross-provider distributed transaction is implied.

Change `UploadedFileStorageStats` and both repository aggregations to report exact retained count/bytes only when there are no unknown completed records. Otherwise return unavailable totals and surface `storage-accounting-incomplete`; do not enumerate blob providers. Add retention-state indexes or equivalent bounded provider queries where they materially support the aggregation. Update `Startup.LogStartupStateSummaryAsync` to log unavailable accounting without presenting unknown legacy data as exact stored bytes.

Add a thread-safe `CleanupRunStatus` singleton holding an immutable snapshot. `ShareCleanupRunner` records a completion timestamp from `TimeProvider`: no per-share failures is `success`, a returned result with failures is `partial-failure`, a non-cancellation exception records `failure` before rethrowing, and failure to acquire the coordination lease records `skipped`. Caller cancellation does not replace the last completed snapshot. Both scheduled and administrative cleanup already flow through the runner and therefore share one process-local view.

Extend `ShareStatusCounts` and `IShareMetadataRepository.GetStatusCountsAsync` to return the six documented 64-bit lifecycle/cleanup counts from one timestamp, updating LiteDB and MongoDB implementations and their existing statistics tests. Keep classification provider-side for MongoDB and bounded through indexed predicates where practical; do not materialize share or file records in the status service.

Add `server status` command nodes, options, and dispatch to `CliApplication`, following the existing handler/API-client split in a new status-focused namespace. Attach `--server-url`, TLS options, `--upload-token`, `--admin-token`, `--upload-authorized`, `--verbose`, and `--json`, validating mutually exclusive modes before making a request. When the parser recognizes `server status` and `--json`, route parsing, option-validation, configuration, and TLS-setup failures through the status JSON writer with exit code `1` rather than returning stderr-only; no banner or diagnostic may be written to stdout. The API client uses a bounded control-plane deadline that accommodates the five-second server status-collection budget, caller cancellation, and the shared TLS factory.

Use mode-specific source-generated CLI result records with a common base containing server URL, reachability, CLI version, protocol compatibility, and stable outcome; include the selected server projection only when a valid response was received. JSON mode writes exactly one result even for usage, configuration, TLS setup, connectivity, authorization, capability-disabled, incompatibility, or readiness failures. A `404` from an explicitly selected upload or admin status route maps to `capability-disabled` and exit code `1`; other missing or malformed status responses remain unexpected failures unless a valid response establishes protocol incompatibility. A bodyless `503` from scoped-status authentication maps to `not-ready` and exit code `2` without an upload projection, while `401` maps to unauthorized and exit code `4`. Human mode renders the common preflight first, then upload limits or admin detail for the selected tier. Apply exit precedence as connectivity/TLS, authorization,
capability-disabled, incompatibility, not-ready, healthy, with usage and unexpected protocol/response failures returning `1`.

Implement admin status auditing as a reusable endpoint filter or middleware driven by explicit operation metadata so authorization failures are observable as well as handler outcomes. Use operation `admin-status-view` and outcomes `success`, `unauthorized`, `invalid-request`, `cancelled`, and `failure`; log success/cancellation at information, unauthorized/invalid request at warning, and failures at error. Include only operation, outcome, HTTP status, and elapsed time, and never serialize headers, credentials, identifiers, response records, configuration, or exceptions into audit properties.

Cover API projections and authorization in `ShadowDrop.Api.Tests`, CLI mode selection/rendering/exit behavior in `ShadowDrop.Cli.Tests`, health and cleanup state with sociable unit tests and manual test doubles, and persistence accounting through the existing LiteDB tests and MongoDB integration fixture. Prove shared-Mongo single probing, the single status-collection deadline across probes and statistics, statistics timeout/failure degradation without `500`, caller cancellation, all-capabilities-disabled public status, invalid credentials versus unavailable credential storage, disabled-tier `404` handling, JSON parse/validation/configuration/TLS failures, legacy unknown accounting, idempotent retained-to-deleted transitions, cleanup retry after accounting failure, startup logging, audit redaction, and release/native-AOT JSON metadata. Keep provider-backed integration coverage focused on parity while exercising most behavior in unit tests.
