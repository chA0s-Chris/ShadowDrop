# Add operator share listing API and CLI

> Issue: [#171](https://github.com/chA0s-Chris/ShadowDrop/issues/171)

## Rationale

Give administrators a deterministic, scriptable view of share lifecycle, cleanup, and retained-storage state without requiring persistence access or exposing share capabilities, credentials, filenames, storage keys, cryptographic metadata, or provider internals. Keep listing bounded and equivalent across LiteDB/filesystem and MongoDB/GridFS, with stable filtering, pagination, errors, auditing, and CLI output built on operational protocol version `1` from #170.

## Technical Details

Add protocol-v1 share-list contracts and stable constants under `ShadowDrop.Shared` and register them with the existing source-generated JSON context so the API and Native AOT CLI use one wire shape. The page contains `protocolVersion` sourced from `OperationalStatusProtocol.CurrentVersion`, `items`, `nextCursor`, and 64-bit `totalMatching`. Each item contains lower-case UUID `D` `shareId`; UTC round-trip `createdAtUtc`, `expiresAtUtc`, and nullable `revokedAtUtc`; a deterministic `statuses` array; `cleanupState`; nullable `lastCleanupAttemptAtUtc`; a deterministic array of distinct `cleanupFailureCategories`; and 64-bit `fileCount` and `ciphertextBytes`. Emit only applicable statuses in the canonical order `active`, `expired`, `revoked`, `cleanup-pending`, `cleanup-failed`, `cleanup-completed`; emit cleanup state as exactly `pending`, `failed`, or `completed`, mapping missing or unrecognized legacy values to `pending`; and emit categories in the canonical order
`upload-metadata-missing`, `metadata-unavailable`, `blob-delete-failed`, `unknown`. Arrays are empty rather than null, fields are never conditionally omitted, and only the documented timestamps and cursor are nullable. Introduce a source-generated operational error record with the wire shape `{ "reason": string }`, using `unauthorized`, `invalid-request`, `invalid-cursor`, and `operation-failed` for the applicable share-list outcomes.

The stable HTTP surface is `GET /api/admin/shares?status=<value>&status=<value>&pageSize=<1-200>&cursor=<opaque>`. The matching CLI surface is `shadowdrop share list --status <value> --status <value> --page-size <1-200> --cursor <opaque> [--json]`, together with the existing `--server-url`, TLS, and `--admin-token` options. Repetition is the only multi-value form; reject empty, comma-packed, or unknown statuses so normalization is unambiguous. Normalize accepted filters by deduplicating them into the protocol-defined status order before repository use and cursor encoding. Omitting `status`, `pageSize`, or `cursor` means all shares, page size `50`, or the first page respectively; values above `200` are invalid rather than clamped. This deliberately diverges from the older upload-credential listing endpoint, which names the control `limit`, rejects non-positive values, and silently clamps values above its maximum: strict rejection of all out-of-range values keeps scripted operator use
deterministic instead of returning a different page size than
the caller asked for. Document the difference rather than changing that endpoint.

Define lifecycle predicates once in a query model shared by endpoint validation and repository implementations. `active` means not revoked and expiring after the request's captured `nowUtc`; `expired` means expiring at or before it; `revoked` means a revocation timestamp is present; and `cleanup-pending`, `cleanup-failed`, and `cleanup-completed` are exact cleanup-state matches, where pending also covers missing or unrecognized legacy values. The three cleanup statuses carry no lifecycle qualifier, so they keep exactly the meaning `GetStatusCountsAsync` already exposes through `GET /api/admin/status`; extract those predicates into the shared query model and have both the status counts and the list page and count consume them, so the two surfaces cannot drift. These predicates are independent, so one share may have multiple statuses; use the canonical status order for filter normalization and projection. Capture `nowUtc` once through `TimeProvider` before decoding the query into the
repository request, and use that value for the page predicate, returned status projection, and exact count.

Introduce a `ShareListQuery`, opaque `ShareListCursor`, provider page result, and safe summary inputs around `IShareMetadataRepository`. The cursor encodes the operational protocol version, normalized filters, `CreatedAtUtc`, and canonical lower-case UUID `D` sort key using a versioned, URL-safe format; it is an opaque continuation token rather than a persistence bookmark or capability. Decode and validate it before repository access, require exact normalized-filter equality, and apply a strict lexicographic continuation predicate after the last `(CreatedAtUtc, ShareId)` pair. Validate filters and page size before the cursor, so a request carrying both an unknown status and an unusable cursor reports `invalid-request`; cursor validity is defined relative to the normalized filter set, so the filters must be known good first. Do not bind page size so callers may change it between requests. Return an exact count for the full normalized predicate independently of page size and cursor,
while documenting that concurrent lifecycle changes may alter later totals and membership.

Implement provider-native filtering, counting, sorting, and `pageSize + 1` lookahead in `MongoShareMetadataRepository`, and use indexed LiteDB queries plus only page-bounded in-memory projection in `LiteDbShareMetadataRepository`. Both providers already order `ShareId` identically to ordinal canonical lower-case UUID `D` ordering — MongoDB stores it as standard-representation binary that compares big-endian bytewise, and LiteDB compares it through `Guid.CompareTo` — so use that native ordering directly and pin the equivalence with provider-backed tests instead of persisting a separate sort key or backfilling existing records. Mirror the existing `newest_first_listing` credential index for shares in `ShadowDropMongoConfigurator` with descending `CreatedAtUnixTimeMilliseconds` and descending `ShareId`, and index descending `CreatedAtUnixTimeMilliseconds` in LiteDB initialization, evaluating the `ShareId` tie-break only within the equal-timestamp group. Bounded means at most
`pageSize + 1` share documents are materialized and mapped per request, while the exact count evaluates its predicate without materializing documents. Cover the expiration, revocation, and cleanup predicates used by list and count operations with provider-appropriate indexes as well. Avoid loading full `ShareRecord` graphs when a safe list projection suffices, and preserve the existing single-use file index and cleanup-candidate behavior.

Extend `IUploadedFileMetadataRepository` with one bounded batch projection keyed by the distinct file IDs from the current share page, returning only each ID, encrypted length, and retention state needed for aggregation. Implement one provider request per page in MongoDB and one bounded indexed lookup set in LiteDB. Calculate each summary's `fileCount` from share membership and `ciphertextBytes` from this projection, counting retained blobs only: cleanup deletes the blob and marks the record through `TryMarkBlobDeletedAsync` without removing it, so a deleted file contributes `0` and a fully cleaned-up share reports `0` retained bytes alongside its unchanged file count, matching the retained-blob accounting behind `StatusStorageContract`. If any requested file is absent or the projection fails, fail the whole API request with `500` and `{ "reason": "operation-failed" }`; never return a partial page, zero-fill missing data, or infer a ciphertext total. Never read blob providers,
filenames, blob keys, content types, hashes, encryption parameters, plaintext sizes, or owner data for the list projection.

Evolve `ShareRecord`, the LiteDB share document, and `MongoShareDocument` with nullable `LastCleanupAttemptAtUtc` and a collection of sanitized latest-attempt categories. Replace `TryUpdateCleanupStateAsync` with an atomic completed-attempt update that writes state, timestamp from `TimeProvider`, and the distinct category set together. `ShareCleanupService` maps missing upload records to `upload-metadata-missing`, expected metadata-provider read/accounting failures to `metadata-unavailable`, blob deletion failures to `blob-delete-failed`, and otherwise unclassifiable non-cancellation failures to `unknown`; never persist messages, exception types, provider details, IDs, or stack traces. A retry replaces all previous outcome fields, success writes `Completed` with an empty category set, and cancellation exits without recording an attempt. Missing legacy fields map to null and an empty set without migration-time scans.

Add a dedicated share-list application service that validates and normalizes the request, captures time, requests the provider page/count, performs the one batch file projection, and maps only allow-listed shared contracts. Map `GET /api/admin/shares` outside the `RequireAdminBearerToken` group exactly as `/api/admin/status` is mapped, attaching `OperationalAuditMetadata("admin-share-list")`, then the operational audit filter, then `AdminBearerTokenEndpointFilter`. Route-group filters wrap endpoint filters, so only this order lets auditing observe authorization failures and lets this operation return the shared `401` `unauthorized` body without changing the filter every other administrative endpoint depends on. The `{ "reason": "unauthorized" }` body is produced by a share-list-specific result-shaping step — a dedicated endpoint filter between the operational audit filter and `AdminBearerTokenEndpointFilter` that rewrites the bearer filter's bare `401` into the shared error contract;
the generalized operational audit filter remains observation-only, so `/api/admin/status` and every other administrative endpoint keep their existing `401` behavior. Administrative operations stay gated by `ApiExposure.EnableAdminOperations`; when it is disabled the route is never mapped, requests receive a framework `404` outside the operational error contract like every other administrative route, and the CLI reports that through its
generic failure path with exit code `1`. Generalize the status audit metadata/filter into a reusable operational audit filter and attach `admin-share-list`; use the shared outcomes `success`, `unauthorized`, `invalid-request`, `cancelled`, and `failure`, plus the resulting HTTP status and elapsed time only. Audit handling must surround authorization so rejected credentials are observable without recording bearer tokens, query parameters, cursor contents, item identifiers, returned records, or exceptions. Missing or unavailable batch metadata maps to HTTP `500` and audit outcome `failure` without logging identifiers or provider details.

Add share-list command options, handler, API client, and deterministic result writer under `ShadowDrop.Cli/Shares`, following the existing handler/client/configuration/TLS split and resolving credentials only through `CliConfigurationResolver.ResolveAdmin` and `AdminConfiguration`. Human output uses stable field/status/category order and prints the page total and continuation cursor predictably. On success, JSON mode deserializes and serializes the shared page contract exactly once and emits no banner. Configuration, validation, HTTP, authorization, cursor, metadata inconsistency, and unexpected-response failures return exit code `1`, write only a generic diagnostic to stderr, and emit nothing on stdout even when `--json` was selected; output must never echo the admin token, cursor payload, identifiers, or provider details. Register all shared/CLI records with source-generated serializer contexts.
