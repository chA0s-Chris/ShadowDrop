# Add operator share inspection API and CLI

> Issue: [#172](https://github.com/chA0s-Chris/ShadowDrop/issues/172)

## Rationale

Give administrators a detailed, deterministic view of one internal share ID without turning that identifier or the response into a download capability. Reuse the operational protocol and bounded share-summary projection from #170 and #171, keep filename metadata redacted unless explicitly requested, and preserve equivalent behavior across supported metadata and blob-provider combinations.

## Acceptance Criteria

- [x] Add admin-authorized `GET /api/admin/shares/{shareId}` and `shadowdrop share inspect <share-id>` surfaces that use the existing admin-token configuration path.
- [x] Default the admin API to omitted `includeFilenames`, accept only the exact ordinal values `true` and `false` (rejecting `True`, `1`, and repeated values with `400` and `invalid-request`), and add CLI `--include-filenames` as the only explicit filename opt-in; no public route accepts this control.
- [x] Return the shared summary fields plus a `files` array whose entries contain only `fileId`, `ciphertextBytes`, `retentionState`, nullable `originalFilename`, and nullable `displayName`.
- [x] Report `retentionState` as `retained` for a file whose ciphertext is still stored, `deleted` for a reclaimed blob, `unknown` for a legacy record whose retention was never recorded, and `missing` for a referenced file whose uploaded-file metadata row is gone, so a zero `ciphertextBytes` is never ambiguous.
- [x] Format share and file identifiers as canonical lower-case UUID `D` strings and timestamps as UTC ISO 8601 round-trip strings.
- [x] Return both filename fields as `null` by default in API, deterministic human, and JSON output, and populate them only after the explicit API or CLI opt-in.
- [x] Document filename exposure as sensitive and never include filenames in audit events, diagnostics, summary output, or default inspection output.
- [x] Never return share or download bearer tokens, token hashes or lookup identifiers, encryption material, credential identifiers, blob keys, persistence paths, plaintext hashes, raw configuration, or internal exceptions.
- [x] Keep public download resolution token-based so neither an internal share ID nor any inspection response can be used as a download capability.
- [x] Reuse the bounded batch uploaded-file metadata projection introduced by #171 and never perform one metadata query per file or scan a blob provider.
- [x] Return the share summary with a zero-byte `missing` file entry when a referenced file has no metadata projection, and reserve `operation-failed` for repository, query, and inconsistent-projection failures.
- [x] Return `404` with `{ "reason": "not-found" }` for an unknown share and make the CLI return exit code `6` for that outcome, documented as specific to `share inspect`.
- [x] Return stable shared operational error contracts for authorization, invalid requests, and provider or inconsistent-projection failures without leaking request or persistence details.
- [x] Produce concise deterministic human output and exactly one documented inspection JSON value on stdout on success, with banners, warnings, and diagnostics kept off stdout whenever `--json` is selected.
- [x] Emit safe `admin-share-inspect` audit events containing only operation, outcome, HTTP status, elapsed time, and one boolean recording whether filename inclusion was requested, and leave every other operation's audit record unchanged.
- [x] Provide equivalent contracts, redaction, not-found behavior, bounded lookups, and failure semantics for LiteDB/filesystem and MongoDB/GridFS deployments.
- [x] Add automated authorization, request validation, default-redaction, filename-opt-in, contract serialization asserting the inspection contract is registered on `OperationalStatusJsonSerializerContext` and round-trips through source-generated metadata without reflection fallback, stdout/stderr, not-found and exit-code, batch-lookup, missing-projection degradation, audit-redaction, and provider-parity tests.
- [x] Update `README.md`, `docs/API.md`, `docs/CLI.md`, `docs/DEPLOYMENT.md`, and `docs/SECURITY_TRADEOFFS.md` with routes, options, examples, retention-state values, a `share inspect` exit-code table, and filename-sensitivity guidance.

## Technical Details

Add a protocol-v1 share-inspection contract under `ShadowDrop.Shared` and register it with `OperationalStatusJsonSerializerContext` so the API and Native AOT CLI serialize one wire shape. Flatten the fields from `ShareListItemContract` into the inspection result alongside `protocolVersion` and `files`: `shareId`, lifecycle timestamps and statuses, cleanup state and latest sanitized failure categories, `fileCount`, retained `ciphertextBytes`, and the file entries named in the acceptance criteria. Keep every field present, use empty arrays rather than null, preserve the share's file order for deterministic output, and reserve null in file entries for redacted or absent filename values. A deleted ciphertext blob contributes zero bytes to its file entry and the summary, matching the retained-storage semantics of share listing and admin status. Because a zero byte count alone cannot distinguish an empty file from a reclaimed or unknown one, each file entry also carries `retentionState`;
add its stable values (`retained`, `deleted`, `unknown`, `missing`) to the shared contracts next to the existing status and cleanup-category constants. Map the first three exhaustively from the projection's `BlobRetentionState`, which already carries an `Unknown` member for a record written before retention accounting and must keep that meaning on the wire, and assign `missing` only when the batch projection returned no row for a referenced file. Never fall back to a default value and never consult a blob provider. This is a deliberate addition to the field list named in the issue.

Introduce a `ShareInspectionService` in `ShadowDrop.Api/Shares` that captures one `nowUtc`, loads the share once through `IShareMetadataRepository.GetAsync`, and maps its safe summary with the same `ShareLifecycle` rules used by `ShareListService`. Listing and inspection operate on different records — `ShareListRecord` carries `FileIds` while `ShareRecord` carries `Files` — so make the shared logic record-agnostic instead of adapting one record into the other: change `ShareLifecycle.Statuses` to take the lifecycle values (`expiresAtUtc`, `revokedAtUtc`, `cleanupState`) rather than `ShareListRecord`, and extract the summary mapping into a helper both services call with those values plus `lastCleanupAttemptAtUtc`, `cleanupFailureCategories`, `fileCount`, and retained `ciphertextBytes`. `ShareListService` keeps its current input and behavior. Request all distinct referenced file IDs in one `IUploadedFileMetadataRepository.GetListProjectionsAsync` call, index the returned projections in
memory, and combine encrypted length and retention state with the share-specific file order and optional display names. A referenced file with no projection is expected rather than exceptional, because share cleanup deletes uploaded-file metadata entry by entry before it deletes the share record and can leave a `cleanup-failed` share pointing at reclaimed rows; report that file as `missing` with zero bytes, count it in `fileCount`, exclude it from the summary total, and still return the inspection, so the shares an operator most needs to diagnose stay inspectable. Reserve `operation-failed` for repository or query failures and for a projection set that is internally inconsistent, such as duplicate file IDs. Do not call `GetAsync` once per file, enumerate filesystem, GridFS, or S3 contents, or add a provider-specific inspection path.

Apply filename redaction while constructing the allow-listed response, before it reaches endpoint, CLI, audit, diagnostic, or logging code. `originalFilename` comes from the share's recorded file entry and `displayName` remains the share-specific recipient-facing override; populate both only when the authenticated request explicitly selected filename inclusion. Never reuse `UploadedFileProjection`, `ShareRecord`, or persistence documents as response contracts because they contain cryptographic, token-derived, ownership, or storage fields. Keep existing `/d/{token}` resolution through `GetByShareTokenHashAsync`; the inspection endpoint must not mint, reconstruct, accept, or return a share token, download bearer token, URL, key, or other download input.

Map `GET /api/admin/shares/{shareId}?includeFilenames=<true|false>` in `AdminEndpoints` only when administrative operations are enabled. Keep the endpoint outside the admin route group, as the status and list endpoints are, so `OperationalAuditEndpointFilter` surrounds `AdminBearerTokenEndpointFilter` and observes authorization failures. Attach operation metadata `admin-share-inspect`, and reuse `ShareListUnauthorizedResultFilter`, which already shapes any `401` into the shared `{ "reason": string }` contract with no share-list-specific logic; rename it to drop the share-list prefix rather than writing a second filter. Extend `OperationalErrorReasons` with `NotFound = "not-found"`. Parse the route value and query explicitly after authorization: malformed or empty IDs, repeated query values, and filename values other than the exact ordinal `true` or `false` return `400` with `invalid-request`; missing shares return `404` with `not-found`; invalid credentials return `401` with
`unauthorized`; and unexpected repository or projection failures return a generic `500` with `operation-failed`. Because the filename opt-in discloses sensitive metadata, the audit record must show that it was exercised: let the endpoint publish that single Boolean through `HttpContext.Items` and have `OperationalAuditEndpointFilter` log it as `FilenamesIncluded` only for `admin-share-inspect`, leaving every other operation's audit line byte-identical. Every `admin-share-inspect` line carries the property, defaulting to `false` when the endpoint never ran, so authorization and not-found records keep the same shape as successful ones. Audit records otherwise use only the operation, allow-listed outcome, resulting status, and elapsed time and never record the share ID, query value, filenames, response, credentials, provider data, or exception text. S3 needs no separate parity coverage here because inspection reads retention state from uploaded-file metadata and never touches a blob
provider.

Add `share inspect` command wiring to `CliApplication` with a required share-ID argument, the existing server URL, TLS, admin-token, and JSON options, plus `--include-filenames`. Follow the `ShareListCommandHandler` and `ShareListApiClient` split, resolve credentials only through `AdminConfiguration`, canonicalize a valid ID before constructing the URL, and send `includeFilenames=true` only when selected. Validate locally before making a request. A successful JSON invocation writes the shared inspection contract exactly once; human output uses a stable field and file order, prints each file's `retentionState` alongside its byte count, and renders redacted filename values explicitly as `null`. An API `404` with the documented reason returns exit code `6`; authorization, invalid request, connectivity, malformed response, protocol mismatch, and operation failures retain the generic nonzero operational failure behavior, write a concise non-sensitive diagnostic to stderr, and do not write
partial data or diagnostics to stdout. Exit code `6` is specific to `share inspect`: document it in a table in the `docs/CLI.md` share-inspection section covering `0`, `6`, and `1`, leave the `server status` table untouched, and keep `token inspect` and `share revoke` returning `1` for a missing resource.

Exercise the service and endpoint primarily with sociable unit tests in `ShadowDrop.Api.Tests`, including authorization-before-binding, one captured time, lifecycle parity with list summaries, file ordering and counts, ciphertext across every `retentionState` value, exactly one bounded metadata projection, a share whose referenced metadata row is missing, duplicate projections, every redaction/opt-in combination, error contracts, disabled admin operations, and audit property redaction including the filename-disclosure Boolean and the absence of any other added property. Extend the LiteDB repository tests and MongoDB integration fixture only as needed to prove the existing batch projection supplies equivalent results without N+1 reads. In `ShadowDrop.Cli.Tests`, cover command wiring, ID and option validation, URI construction, admin credential resolution, deterministic human and JSON output, stdout/stderr isolation, protocol validation, and exit code `6`. Add exact shared-contract
serialization tests so lower-case UUIDs, UTC round-trip timestamps, null filename fields, and source-generated metadata remain stable.

Keep share listing, filtering, pagination, mutation, deletion, revocation, cleanup commands, public filename exposure, and new download capabilities out of scope. `ShareListService` therefore keeps failing a whole page when a share references reclaimed uploaded-file metadata; making listing as tolerant as inspection is a separate change and needs its own issue. Because this is the final child of #142, its implementation pull request includes both `Closes #172` and `Closes #142` only after #170 and #171 are merged; it must not close the umbrella while either prerequisite remains open.
